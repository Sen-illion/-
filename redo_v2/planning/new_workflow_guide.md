# 本次重做的新工作流程（人读版）

## 1. 工作原则

本次重做采用“先为全部小问建立初步模型，再逐问闭环”的方式。开始时不只列出 Q1–Q3 的目录和依赖，而要为每问形成可审阅的变量、参数、目标函数、核心约束、方法候选、baseline、风险和接口说明；进入执行阶段后，一次只推进一个问题或一个确有强依赖的问题组，不一次性生成或运行全部问题的代码。

人负责模型取舍、假设必要性、结果接受和论文主张；AI 负责数据核对、数学与代码一致性、可复现运行、约束检查和材料整理。带有“初步倾向”“暂定”的回答只作为偏好记录，不视为最终授权。

## 2. 推进顺序

1. 全题初步建模：完成问题拆解、依赖图、共享数据口径、全局符号，并为每问建立含变量、目标、约束、候选方法和 baseline 的初步模型包；不在此阶段批量生成代码。
2. Q1 闭环：详细调整模型 → 人工确认 → 实现计划 → 主方法与 baseline 代码 → 约束复核 → 正式实验 → 稳健性检验 → 人工判断与冻结。
3. Q2 闭环：继承已确认的 Q1 数据和约束口径，单独完成不确定性模型、代码、实验和稳健性。
4. Q3 闭环：在已确认的 Q2 框架上加入相关性及替代/互补关系，单独比较关联前后结果。
5. 若若干小问关系紧密，可在“建模层”共同定义共享情景生成器、变量或约束，但每问仍保留独立的状态、运行摘要、稳健性证据和结论。
6. 全部小问完成后，才进行跨问题一致性、附件 3 Excel、论文整合和最终审计。

## 3. 每问的阶段门

- G1 问题已框定：目标、数据、约束、输出和成功标准齐全。
- G2 方法已筛选：主候选、可用 baseline、风险探针和备用触发条件齐全。
- G2.5 人工已选方法：只有明确的最终选择才能放行代码生成。
- G3 代码与实验已审查：主方法和 baseline 均运行，且通过输入、约束、复现和输出检查。
- G4 结果与稳健性已判断：人工根据正式证据选择继续、调整或启用备用方法。
- G5–G6 论文与最终审计：只在数值冻结后进行。

任何上游数据口径、数学假设或参数发生变化，都只重跑受影响的问题，不机械地重跑全部问题。

## 4. 每个关键阶段的双层材料

### 人读/论文准备层

- 问题分析与依赖说明；
- 模型假设及适用边界；
- 符号、目标函数和约束解释；
- 候选方法比较与选择理由；
- 算法流程、实验解释和稳健性结论；
- 最终可改写进论文的方法与结果段落。

### AI 交互/机器层

- 每问 manifest：当前阶段、阻塞项、允许动作和下一步；
- JSONL 决策账本：忠实保存人的原话、状态和证据；
- 方法卡、风险探针、实现契约和运行摘要；
- 冻结数值及来源路径。

此外，全题维护 `planning/solution_process/global_modeling_map.md`，每问维护 `methods/Qx/qx_modeling_process.md`。这些文档在每个建模或模型选择的实质步骤更新，解释“为什么和怎么做”，并包含可直接交给其他 AI 的接续状态以及标注为 DRAFT/VERIFIED 的论文候选内容。不为纯格式化等微小机械操作制造冗长报告，但不能只保留最终方法卡或机器 JSON。

## 6. “产量过度集中”与“连续重茬”的区别

两者相互独立：

- 集中度描述全局结构，例如少数作物占全部种植面积或总产量的比例过高。现有风险探针实际使用的是“前 5 作物面积占比”等指标，因此更准确地说是“种植分配过度集中”。
- 连续重茬是局部时间约束：同一地块在相邻种植期或相邻适用年度不能连续种同一作物。

一个方案可以只在少数作物之间轮换，从而集中度很高但仍不重茬；也可能总体作物很丰富，却在某个地块上发生重茬。因此不能用集中度替代逐地块、逐季、逐年的重茬检查。

当前数据中有 54 个地块、41 种作物和 87 条 2023 年种植记录，可用于建立 2024 年的重茬初始状态以及三年豆类覆盖初始状态；但没有 2024–2030 年真实种植观测。隔离副本中的探针摘要声称 baseline 的 574 条分配通过了重茬检查，但这些分配明细未被带入本次重做，所以正式结论必须由重做后的方案和约束检查器重新产生。

### 强制同步规则

每次产生文件修改后，必须在同一阶段完成以下动作，不能只更新本地或只更新 GitHub：

1. 确认所有新增、修改和删除都位于 `redo_v2`。
2. 运行格式、结构及必要的内容校验。
3. 只暂存 `redo_v2`，创建可追踪提交并推送到 `origin/codex/redo-v2`。
4. 核对本地 `HEAD` 与远端分支提交号完全相同。
5. 核对分支顶层只有 `redo_v2`，并确认本地工作树没有未提交的 `redo_v2` 变更。

只有五项全部通过，才可向用户报告本轮更新完成。本地 `.git` 是 Git worktree 必需的隐藏元数据指针，不属于项目交付文件，也不会显示在 GitHub 文件树中。
