# 可复用的逐问数学建模提示词

以下内容可在其他数学建模项目开始时直接提供给 Codex/其他 AI，并把方括号内容替换为项目实际信息。

```text
这是一个新的数学建模项目。请采用“先建立全题骨架，再逐问闭环”的工作方式，不要一次性完成或运行所有小问。

一、总体组织
1. 先解析全部题目，建立各小问的目标、输入、输出、约束、成功标准、依赖关系和共享数据口径。
2. 建立全局符号表、数据画像、模型假设表，以及每问的主候选、可用 baseline 和至多一个有明确触发条件的备用方法。
3. 如果若干小问关系很强，可以共同完成共享建模部分；但每问必须分别保留状态、代码、实验、稳健性证据和最终结论。
4. 完成总体骨架后，按 [Q1 → Q2 → Q3 → ……] 逐问推进。除最终一致性复算外，不一次性运行全部问题。

二、每问的闭环
对当前小问依次执行：
问题细化 → 数据与假设核对 → 方法筛选和风险探针 → 展示人工选择卡 → 人工明确选择 → 数学模型详细化 → 实现契约 → 主方法与 baseline 代码 → 代码审查 → 正式实验 → 约束检查 → 稳健性/敏感性检查 → 展示结果选择卡 → 人工确认 → 冻结结果 → 生成论文材料。

用户说“倾向”“暂定”“之后补充”时，只记录为 PROVISIONAL，不得标记为最终决定，也不得据此开始代码生成。涉及模型选择、假设必要性、结果接受和论文主张时必须由用户决定；机械检查由 AI 自行完成。

三、材料要求
每个会影响方法、结果或论文主张的关键节点，同时生成：
1. 人读/论文准备材料：问题分析、假设、公式解释、模型选择理由、算法流程、实验与稳健性解释。
2. AI 交互/机器材料：manifest、JSONL 决策账本、方法卡、风险探针、实现契约、run_summary 和证据路径。

材料应简洁、可追踪、可独立交给另一个 AI 阅读。区分题面事实、数据观察、人工假设、模拟设定、推导结论和已验证结果；不得把模拟参数写成观测事实，不得把未收敛解写成最优解。

四、变更与复算
数据、单位、符号、公式或关键参数变化时，判断影响范围，只重跑受影响的小问。冻结后的数值必须按“解冻 → 修改规范来源 → 重跑 → 重冻结”处理。最终论文只引用冻结且有来源的数字。

五、文件和版本控制
所有新成果只写入 [项目隔离目录]。原始数据只读，清洗数据另存。每次产生文件修改后，都必须在同一阶段提交并推送到 [Git 分支]；推送前列出本次新增/修改文件，不把其他历史项目或无关目录带入分支。推送后必须验证本地 HEAD 与远端提交号一致、分支文件树与本地交付目录一致、交付目录没有未提交变更。任何一项不一致时，不得报告“更新完成”。

六、开始方式
先给我一份简短的全题结构和当前唯一下一步。遇到真正需要人工判断的地方，用不超过三个互斥选项提问；在我回答前不要跨过对应阶段门。
```
